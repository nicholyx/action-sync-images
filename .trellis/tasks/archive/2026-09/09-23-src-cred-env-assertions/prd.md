# 补上源凭证的环境变量通路与多仓库告警的断言

对应 Issue：nicholyx/action-sync-images#136

## Goal

这不只是覆盖率问题——**是安全问题**。

`usage` 明确要求「CI 等自动化场景**应当**用环境变量」（因为命令行对同机进程可见，
且工作流里有一句 `执行：./scripts/sync.sh ${args[*]}` 会原样打印），
而三条环境变量兜底分支与相关的两条告警**零覆盖**。

CI 里只测了 `SYNC_SRC_CREDENTIALS`（文件内容语义），没测那三条。

## 要实现覆盖的行为（已实测采集）

### 三条环境变量兜底

| 变量 | 实测行为 |
| --- | --- |
| `SYNC_SRC_USERNAME` + `SYNC_SRC_PASSWORD` | 「源仓库凭证已装载（1 个仓库）：`<推导出的 host>`」 |
| `SYNC_SRC_REGISTRY` | 指定 host，**并抑制**「应用到多个源仓库」告警 |
| （对照）不设 `SYNC_SRC_REGISTRY` 的多源场景 | 出现「凭证被应用到多个源仓库」告警 |

### 两条参数校验

```text
只给 --src-username              → rc=1「--src-username 与 --src-password 必须同时提供（当前只给了一个）」
只给 --src-registry              → rc=1「--src-registry 需要与 --src-username / --src-password 一起使用」
```

### 多仓库告警的两侧

```text
--src 'nginx:1.27,quay.io/foo/bar:1' --src-username alice --src-password s3   → 出现「凭证被应用到多个源仓库」
同上 + SYNC_SRC_REGISTRY=docker.io                                            → 该告警消失（实测 0 次）
```

## Requirements

### R1 为什么 `SYNC_SRC_REGISTRY` 是最要紧的一条

它丢失时脚本会「自动从镜像列表推导 host」——于是**凭证被发往使用者未指定的仓库**。

源码里有两处在防这件事（`sync.sh:1466` 与 `1528-1534`），但**没有任何断言**。

断言要覆盖「**设了它就真的只发那一个**」与「**没设时那条告警真的出现**」两侧——
只测一侧无法区分「生效」与「恰好只有一个源」。

### R2 环境变量与命令行参数走的是同一条通路

断言里应当**至少一组**验证「环境变量设进去之后，日志里的 host 与预期一致」——
只断「有『已装载』这行」不够，那在 host 推导错时也会通过。

### R3 断言放哪

并入现有的「验证凭证映射文件」步骤（`ci.yml` 的 smoke-test，`--src-credentials` 那组）。
脚手架现成，且按 `.trellis/spec/maintenance/index.md` 的「改动 CI 步骤」一节：
新增前先搜 job 里已有什么、不要另起容器。

### R4 凭证不得出现在输出里

现有的凭证断言里有「日志中不含凭证」的检查——新增的用例要沿用同一条判据。
**尤其**：环境变量传的密码与命令行传的密码都要检查不进日志。

## Acceptance Criteria

- [ ] **AC1** 三条环境变量各有用例，且断的是「host 与预期一致」而不只是「有装载日志」
- [ ] **AC2** `SYNC_SRC_REGISTRY` 的**两侧都测**（设了→告警消失；没设→告警出现）
- [ ] **AC3** 两条参数校验各一条断言，**断文案**（退出码 1 可能来自任何一条 `die`）
- [ ] **AC4** 凭证（用户名与密码）不出现在任何新增用例的输出里
- [ ] **AC5** **变异验证**：每条断言都要能证明非恒真。至少要：
      - 把 `SYNC_SRC_REGISTRY` 的生效逻辑去掉 → AC2 的「告警消失」那条变红
      - 把「多仓库告警」那段删掉 → AC2 的「告警出现」那条变红
      - 把某条参数校验的文案改掉 → AC3 对应那条变红
- [ ] **AC6** `bash -n`、`shellcheck`、`./scripts/lint.sh` 全绿；CI 两个 job 全绿

## Constraints

- **不改生产代码**（只加断言）。若发现某条行为本身有问题，报告而不要顺手改
- 兼容 bash 3.2
- **不要用真凭证**：用 `alice` / `s3cret` 这类明显假的值（与现有凭证用例一致）
- `--dry-run`（凭证只落临时文件 + 打日志，不需要网络）

## Out of Scope

- `--src-credentials` 的按仓库映射（已有覆盖，在 `ci.yml` 的「验证凭证映射文件」）
- 凭证的加密/存储方式

## Notes

- 判据是「**凭证发给了谁**与预期一致」，不是「有没有装载」
- 这个 issue 的价值一半在「补覆盖」，一半在**把那条安全告警钉住**——
  它是「凭证发了出去但发错了地方」的唯一提示，而它此前没有任何测试
