# 坏掉的历史报告：既不静默跳过，也不整体崩掉

## Goal

让两条消费历史报告的路径在遇到**无法解析的报告**时行为一致且如实：跳过、并说明跳过了什么——而不是各自「整体崩掉」或「静默丢弃」。

## Background

### 现状（2026-09-20 本地复现）

**同一个坏文件，两条路径，两种坏行为。**

复现用的坏报告，模拟 v1.15.0 之前产出的那一类（镜像名含 `"`，`printf` 裸拼接的产物）：

```json
{"generated_at": "2026-09-01T00:00:00Z", "total": 1, "success": 0, "skipped": 0, "failed": 1,
 "images": [{"source": "a"b:1", "dest": "d", "status": "failed", "seconds": 1}]}
```

**路径一：`history.sh`——整体崩掉**

```bash
# 目录里一份好报告 + 一份上面这种坏报告
./scripts/history.sh --dir /tmp/badhist
# [信息] 共读取 2 份报告
# jq: parse error: Invalid numeric literal at line 34, column 18
# 退出码 5
```

一份坏文件让**全部**历史分析失效（`jq -s` 把整批文件一起喂进去，一个坏则全废）。而且报错**不指明是哪个文件**——使用者不知道该删哪份，只能自己二分查找。

**路径二：`sync.sh` 的 `fetch_sync_history`——静默丢弃**

```bash
jq -r 'select(.images != null) | …' "$f" >> "$out_file" 2>/dev/null || true
```

坏文件被 `2>/dev/null || true` 吞掉，**没有任何提示**。后果比路径一更隐蔽：

```
坏报告少解析一份 → out_file 里的历史记录少一段
  → count_consecutive_failures 少算
  → 「连续第 N 次失败」偏小
  → 本该触发的失败通知被静默跳过
```

`--notify-after-failures` 是「连续失败多少次才通知」的阈值，它依赖这个计数。计数偏小意味着**该响的警报不响**。

### 为什么现在做

v1.15.0 修掉了「**新**报告会产出坏 JSON」（[#103](https://github.com/nicholyx/action-sync-images/issues/103)），但 artifact 保留期（默认 30 天）内的**旧坏报告仍然在**。修的是未来，过去还没人管——而这恰恰是「坏数据真实存在」的窗口期。

### 与既有原则的关系

两条都是 `guides/index.md` 里已确立原则的反面：

| 原则 | 被违反的点 |
| --- | --- |
| 「错误的信息比没有信息更糟，因为它会被当成结论」 | 静默丢弃让「连续的失败次数」看起来完整，实际少算了 |
| 「排除/筛掉的东西必须可见」 | 被跳过的报告没有任何计数或说明 |

## Requirements

- **R1** 无法解析的报告**跳过**，不让整体分析失效
- **R2** 跳过必须**可见**：有计数、有说明，能看出**是哪份**（至少给得出文件名）
- **R3** 两条路径的行为**一致**（同一份坏数据，用户看到同一种交代）
- **R4** **不改变退出码语义**。既有惯例写在 `scripts/history.sh:990-992` 的注释里：「无法判定（查不成）不触发 2——网络抖动和匿名访问不该让退出码失去『需要处理』的含义」。坏文件属于「无法判定」，因此**不触发 2**
- **R5** 全部报告都坏时，报错要说清**是什么问题**，而不是把 jq 的 parse error 直接抛给使用者
- **R6** 好的报告照常分析，结果数字**不受坏文件影响**（不是「整体作废」也不是「凑合算」）
- **R7** 不新增命令行参数（沿用既有口径：为极少调整的值增加表面积不划算）

## Acceptance Criteria

- [ ] 一份好 + 一份坏 → 趋势正常输出（基于好的那份），且明确告知跳过了 N 份
- [ ] 告警里能定位到**具体文件**（文件名或路径）
- [ ] 全部坏 → 明确报错说明「没有可解析的报告」，不是裸的 `jq: parse error`
- [ ] `fetch_sync_history` 遇到坏报告时**计数并告警**，不再静默；调用方据此能判断历史是否完整
- [ ] 退出码语义不变（坏文件不触发 2；`--check` 的三条路径语义同样不变）
- [ ] 既有断言不破（CI 里 history.sh 的三条：趋势聚合、`--check` 聚合、`--report-dir` 落盘）
- [ ] CI 有对应断言，且断言**先在本地复现过**（红 → 绿）
- [ ] macOS 自带 bash 3.2 下正常
- [ ] `./scripts/lint.sh` 全绿；全仓无 U+FFFD

## Out of Scope

- **不修复已产出的坏报告**——artifact 是历史文件，无法回溯修改；本任务只让消费方不再被它绊倒
- **不改报告的产生逻辑**（v1.15.0 已完成）
- **不给 `history.sh` 加新参数**（如 `--skip-bad`）——按 R7 与既有口径
- **不处理 dry-run 报出非 0 耗时**的问题——那是独立的缺陷（v1.15 的质量检查阶段发现，已记进 `bash-rules.md` 并标注「尚未修改」），混进来会污染本任务的验证边界
- **不处理 `gh run list` 的其他吞错点**——`history.sh` 的运行列表获取已在 #98 修过；`sync.sh:2822` 属另一条路径，本任务只碰它与坏报告相关的**解析**部分
