# 失败后的可操作化：Summary 与报告直接给出重跑指引

## Goal

同步失败后，在 Step Summary 与落盘报告里直接给出**失败项的源镜像清单与用法指引**，让使用者从「知道失败了」走到「复制一段、粘一次、重跑」。
承接 v1.11（如实报告）→ v1.14（自动挽回一轮）的脉络，这一段补的是**持续失败之后**的最后一跳。

## Background

### 现状与缺口

- v1.11 让「有附件但下载失败」如实报告，v1.14 让瞬时抖动自动挽回一轮。两次迭代解决的是**「失败被看见、被挽回」**。
- 但**持续失败**（凭证过期、源仓库不可达、目标限流等）时，使用者拿到的仍然只是「哪些镜像失败了」——要重跑，得自己从报告里抄出失败镜像、拼成下次运行的输入。
- 缺口：从「知道失败」到「重跑」之间，仍有一段纯手工、容易抄错的劳动。

### 已确认的约束（来自 `.trellis/spec/`，改动不得违反）

- **凭证不进命令行、不进日志**（`spec/guides/index.md` 原则 6）：重跑指引**绝不能**包含凭证。
- **检查与搬运分开**（原则 4）：重跑是「动作」（有副作用），只对会推送的同步模式给出。
- **失败要能定位到最小单元**（原则 8）：记录粒度是「每个镜像 × 每个目标」。
- **排除/筛掉的东西必须可见**（原则 2）：被 `--filter`/`--exclude` 排除的镜像仍出现在结果表并标注原因。
- **错误的信息比没有信息更糟**（原则 1）：拿不到构造指引所需信息时，宁可不给，也不能给一条跑起来会误伤的指引。
- **兼容性**：macOS 自带 bash 3.2 是一等公民（原则 9 + `spec/engine/bash-rules.md`）。

### 研究结论：可复用的能力（2026-09-17 调研，已确认）

- **失败集良构**：`sync-report.json` 的 `images[] | select(.status=="failed")` 直接给出失败集，逐条含 `source` / `dest` / `status` / `platforms` / `source_digest` / `dest_digest` / `seconds`（`scripts/sync.sh:3229-3253`）。
- **失败记录的 `source` 是规范化后的串**（已去掉 `docker://` 前缀：`scripts/sync.sh:1649` 赋值，`:1657` / `:1787` 写入）——正好可以直接粘进工作流的 `images_src`（工作流文案本就写着「无需 docker:// 前缀」）。注意 `excluded` 行写的是**原始串** `$raw_src`（`:1813`），两者形态不同。
- **Step Summary 由 `sync.sh` 自己写**（同步模式在 `emit_summary`，`scripts/sync.sh:3122-3163`），新增一节**不需要动工作流 YAML**。
- **md 报告与 Step Summary 同源**；json 是独立的另一路（手工拼接，非 `jq`）。
- **有先例可参照**：`--audit` 已给出「去掉 `--audit` 重跑同一条命令即可补齐」的提示（`scripts/sync.sh:2080-2082`，文档 `docs/USAGE.md:636`）；「挑出失败项 → 一轮批量重试」的骨架在 `scripts/history.sh:283-341`（#97）。

### 研究结论：拿不到的信息（已确认）

- **失败原因 `note` 不进 sync 的 md / json / Step Summary**（本任务不做，另开 Issue）。
- 原始调用参数不可从报告还原：`--file` 清单路径、`--dest` 的三种形式之区分、`--skip-existing` / `--verify` / `--concurrency` 等。
- 凭证永不可复现（刻意：只走 env）。
- **`--filter` 是部分匹配 + 只接受一条正则**（重复传参后者覆盖前者，`scripts/sync.sh:424`），且匹配对象是**未规范化**的原始串（`scripts/sync.sh:1224`、`1230`）。
- 工作流的目标地址最终值依赖仓库变量 `vars.ALIYUNCS_REGISTRY`，在代码库之外。

### 工作流侧的入口差异（已确认）

| 工作流 | 失败项能怎么喂回去 |
| --- | --- |
| `Sync-Images-to-AliYuncs` | `images_src`（自由文本，多镜像换行/逗号分隔）——**可直接粘贴** |
| `Sync-Images-to-Harbor` | `images_src` + `images_dest`——**可直接粘贴** |
| `Sync-Batch` | 只有 `lockfile`（仓库内路径）+ `filter` / `exclude`（正则）——**没有自由文本入口** |

四个工作流全部是本地 CLI 调用（`./scripts/sync.sh "${args[@]}"`），参数与 CLI 完全一致，不存在 Actions 专用入口。

## Requirements

### 已定的决策

- **D1 受众**：Actions 页面操作者——在运行页面看到失败、希望就地知道「重跑该填什么」的人。不是假设装了 `gh` 的本地 CLI 使用者。
- **D2 范围**：本任务只交付重跑指引；失败原因（`note`）缺口**另开 Issue**，不并入。
- **D3 `Sync-Batch` 的入口**：复用现有的 `filter` 输入，自动生成**锚定正则**，不改工作流 YAML。
- **D4 不可重跑的失败项**：从清单中排除，并用一句计数交代（如「另有 N 个因引用格式错误，重跑不会成功，未列入」），**不静默消失**。

### 需求

- **R1** 同步失败后，在 **Step Summary** 与落盘报告（md + json）中给出失败项的**源镜像清单**，可直接复制粘贴到对应工作流的输入。
- **R2** 指引里的镜像清单**不含任何凭证**（Actions 形态天然满足）。
- **R3** 口径单一来源：同一份失败集数据驱动 Step Summary 与报告，不得两处各算一遍。
- **R4** 失败项为空时不出现该节（全绿不打扰）。
- **R5** 拿不到构造指引所需信息时宁可不给，也不能给一条会误跑的指引（原则 1）。

## Acceptance Criteria

- [ ] 同步有失败项时，Step Summary 与落盘报告各新增一节「重跑」；**全绿时该节完全不出现**。
- [ ] 有 `images_src` 入口的工作流（Aliyuncs / Harbor）给出**可粘贴的镜像清单**，每行一个源镜像、规范化后的形态（无 `docker://` 前缀），可直接粘进 `images_src`。
- [ ] `Sync-Batch` 给出**锚定 filter 正则**，可直接粘进现有 `filter` 输入；正则能精确命中失败项，不因部分匹配带出同前缀的其它 tag。
- [ ] `引用格式错误` 这类重跑必然失败的项被排除，并以计数句交代，读者能知道「有东西没列入、为什么」。
- [ ] 同一份失败集数据同时驱动 Step Summary、md 报告与 json 报告的机器可读字段，**口径单一来源**。
- [ ] 指引中**不含任何凭证**（webhook、用户名、密码）。
- [ ] macOS 自带 bash 3.2 下可运行（无 `declare -A` / `mapfile` / `wait -n`；空数组遍历前判长度）。
- [ ] `./scripts/lint.sh` 全绿；新增断言在本地先复现过再进 CI。

## Out of Scope

- 失败原因（`note`）进 sync 报告——另开 Issue。
- 只读检查模式（`--audit` / `--check-updates` / `--audit-lock`）的重跑指引。只读检查的重跑即原样重跑，没有「挑出失败项」的语义（原则 4「检查与搬运分开」）；`--audit` 已有的「去掉 `--audit` 重跑同一条命令」提示已覆盖其真实需求。
- 多目标场景。四个工作流全部是单目标调用（`--dest` / `--dest-exact` 各传一个值），多目标只存在于本地 CLI。实现时按 `source` 对失败行去重即可。
- **自动重跑**：v1.14 已做过一轮自动重试，本任务只做「把重跑交到人手里」。
- 本地 CLI 形态的完整命令渲染。
