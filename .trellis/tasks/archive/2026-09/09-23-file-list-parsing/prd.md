# 补上 `--file` 清单解析的断言

对应 Issue：nicholyx/action-sync-images#135

## Goal

`--file` / `-f` / `--source-file` 是 `collect_images` 的文件解析分支（`sync.sh:1287-1308`），
**CI 里一行断言都没有**。而它是**两个生产工作流的正式入口**
（`sync-images-batch.yml:153`、`check-registry.yml:149,152`），也是 `docs/USAGE.md` 里被推荐 6 次的用法。

## 要实现覆盖的行为（已实测采集）

### 六项解析行为

| 行为 | 实现 | 若退化的后果 |
| --- | --- | --- |
| `#` 整行注释剥离 | `line="${line%%#*}"` | 镜像名后带注释 → 解析失败或错误引用 |
| 行尾注释剥离 | 同上 | 同上 |
| 空行跳过 | `[[ -n "$line" ]]` | 空引用进候选列表 |
| 首尾空白 trim | 两条 `${line#...}` | 同上 |
| 去重保序 | awk `!seen[$0]++` | 同一镜像推两次（浪费但可见） |
| 文件不存在 → `die` | `sync.sh:1293` | — |

### **合并语义**（最要紧）

`--src` 与 `--file` 是**合并**而非替换——`docs/ARCHITECTURE.md:675` 专门把它当作
一个必须解释的坑记录下来，而它**没有任何测试保护**。

若退化成替换，`--src` 传的镜像会**静默消失**。

### 实测基线（已采集，断言应对上）

```text
① 含「整行注释 / 空行 / 首尾空白 / 行尾注释 / 重复项」的清单 → 待同步镜像 3 个
② --src nginx:1.27 --file（含 redis:7.4）                → 待同步镜像 2 个（合并）
③ -f（短选项）                                            → 待同步镜像 1 个
④ 文件不存在                                              → 退出码 1 +「镜像清单文件不存在：<路径>」
⑤ 空文件 / 纯空白 / 只有注释                              → 退出码 1（「没有提供任何源镜像」）
⑥ 两行且第二行重复                                        → 去重后 1 个
```

## Requirements

### R1 六项解析行为各断言一次

**不要用一个「大杂烩」清单把所有行为一起测**——那样退化任何一项都只是「数量变了」，
无法指出是哪一项坏了。每种行为一个独立用例，断言「待同步镜像 N 个」**且**
清单里的每个镜像都出现在 dry-run 计划里（只断数量会漏掉「数量对但内容错」）。

### R2 合并语义单独一条，且要能区分「合并」与「替换」

`--src A --file B` 的结果必须是 **A 与 B 都在**。断言要**分别**检查 A 与 B 都出现在计划里。

> **修正（质量检查阶段）**：本 PRD 原先在此处写「只断总数的话，若清单恰好有 2 行会恒真」——
> **那是错的**。合并总数 = `|--src| + |清单行数|`，替换总数 = `|清单行数|`，
> 所以只要 `--src` 至少给一个镜像，`N+M > M` 恒成立，**只断总数本来就区分得开**。
> 内容断言（分别检查 A 与 B 都在）的价值在别处——它锁定的是「哪个镜像在里面」，
> 而不是「总数是多少」。原文的错误论证已删。

### R3 文件不存在与「内容为空」要分开

它们是**两条不同的 `die`**（`镜像清单文件不存在` vs `没有提供任何源镜像`），
退出码相同（1）但含义完全不同——断言文案，不只断退出码。

## Acceptance Criteria

- [ ] **AC1** 六项解析行为各有用例，且断言「数量 + 内容都在」
- [ ] **AC2** 合并语义单独一条，**分别**断言 `--src` 与 `--file` 的镜像都在（不是只断总数）
- [ ] **AC3** 文件不存在与内容为空断的是**两条不同文案**，不只断退出码
- [ ] **AC4** 短选项 `-f` 与长选项 `--source-file` 至少各覆盖一次
      （`--file` 已有其它用例覆盖即可）
- [ ] **AC5** **每条断言都做单点变异验证**：把被测的那一步解析（如 `%%#*` 改成 `#*`、
      删掉 trim、换掉 awk 去重、把合并改成替换）后，断言必须变红
- [ ] **AC6** `bash -n`、`shellcheck`、`./scripts/lint.sh` 全绿；CI 两个 job 全绿

## Constraints

- **不改生产代码**（只加断言）。若发现某项行为本身有问题，报告而不要顺手改
- 清单文件用 `mktemp -d` 生成，不留共享路径（CI runner 上多个步骤并行时要安全）
- 断言用 `grep -qF`
- 兼容 bash 3.2
- 新步骤不与 job 内既有步骤争用容器名/端口（见 `.trellis/spec/maintenance/index.md`）

## Out of Scope

- `--file` 与 `--audit-lock` 的互斥（已由 #134 覆盖）
- 清单文件的编码/CRLF 处理（目前没有相关实现）

## Notes

- 这组断言的判据不是「数量对」而是「**内容对**」——数量是最容易碰巧相等的
- AC5 是本任务的重点：解析分支的每一步退化都可能让数量不变而内容变
  （例如 trim 去掉后 `"  redis:7.4  "` 仍会被解析，但引用名带空格）
