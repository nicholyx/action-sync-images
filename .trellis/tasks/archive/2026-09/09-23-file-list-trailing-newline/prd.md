# fix: 清单末尾无换行时最后一行被静默丢弃

对应 Issue：nicholyx/action-sync-images#143

## Goal

`--file` 的清单**末尾没有换行符**时，最后一行会消失——而退出码仍是 0：

```text
$ printf 'nginx:1.27\nredis:7.4' > list.txt        # 两份镜像，无结尾换行
[信息] 待同步镜像 1 个 → r.example.com/x            ← redis:7.4 无声消失
退出码=0

$ printf 'nginx:1.27' > list.txt                    # 单行、无结尾换行
[错误] 没有提供任何源镜像，请用 --src 或 --file 指定  ← 明明提供了
退出码=1
```

**最坏形态是第一个**：退出码 0、日志显示「同步完成」，使用者以为全同步了，实际少一个镜像。

## 根因

`collect_images` 的文件分支用 `while IFS= read -r line`（`sync.sh:1295`），而 `read` 读到**没有换行符收尾的最后一段**时返回非零（EOF 而非完整行），循环体不执行。

**这条规则本项目已记过**（`.trellis/spec/engine/bash-rules.md` 的 printf 那节）：
`printf '%s'` 不输出结尾换行，配 `while IFS= read -r` 会丢掉最后一段——**曾导致 regctl 路径静默丢平台（Issue #27）**。同一条规则，这次踩在清单解析上。

## Requirements

### R1 按仓库既有范本修

`sync.sh:1408` 与 `2640` 已经是正确写法：

```bash
while IFS= read -r line || [[ -n "$line" ]]; do
```

`parse_src_credentials`（`sync.sh:1239` 一带）也是。**照它改，不要自创写法。**

### R2 逐个核查同族位置（**这条最容易漏**）

全仓有 **18 处** `while IFS= read`。**不是每一处都需要改**——从管道/命令替换读的通常安全（上游输出一般带换行），**从文件读的才有风险**。

逐个判断并给出结论（改 / 不改 + 原因）：

```text
scripts/history.sh:307, 399, 1003
scripts/sync.sh:938, 1239, 1245, 1279, 1295, 1314, 1408, 1521, 1678,
               1714, 2640, 3000, 3020, 3058, 3301
```

判据：**数据来源是文件还是管道**。是文件就核对写入方是否可能不写结尾换行。

**特别注意 `1295` 与 `1314`**（都在 `collect_images` 里）——`1314` 是去重阶段，它的输入来自 `candidates` 数组（已带换行），风险不同。

### R3 加断言

三种形态各一条：

- 有结尾换行 → N 个
- **无结尾换行 → N 个**（与前者结果相同，这才是不变量的表述）
- 单行且无结尾换行 → N 个（而不是报「没有提供任何源镜像」）

**这三条要加在 #135 的断言步骤里**（那个步骤已经在测 `--file` 解析）。**若 #135 已合并**，就在其后新增一个步骤或扩充该步骤。

### R4 顺带更新文档

`docs/USAGE.md` 关于清单格式的说明——现在只写「每行一个」。**修好之后不需要提结尾换行**（那才是正确行为），但可以在说明里点明「末尾的换行不是必须的」，免得有人以为必须。

## Acceptance Criteria

- [ ] **AC1** 三种形态（有/无结尾换行、单行无结尾换行）都读到最后一行，退出码与镜像数正确
- [ ] **AC2** 18 处 `while IFS= read` 每一处都有「改 / 不改 + 原因」的结论，**并附证据**（该处数据来源是什么）
- [ ] **AC3** 断言覆盖三种形态；**做变异验证**：把 `|| [[ -n "$line" ]]` 去掉后断言必须变红
- [ ] **AC4** 不引入新行为：有结尾换行的清单逐字节行为不变
- [ ] **AC5** `bash -n`、`shellcheck`、`./scripts/lint.sh` 全绿；CI 两个 job 全绿
- [ ] **AC6** CHANGELOG 记一条（这是**用户可感知的修复**——静默丢镜像）

## Constraints

- 兼容 bash 3.2
- 不改 `read` 之外的行为（例如不要顺手改去重逻辑）
- 若发现某处「看起来该改但其实不该」的，**如实说明理由**，不要为了凑数改它

## Out of Scope

- 清单的 CRLF / 编码处理（目前无相关实现）
- `--src` 路径（`split_images` 走 `printf '%s\n'`，不受影响——但请在报告中确认这一点）

## Notes

- 这属于「**静默丢数据**」，比报错严重：使用者看到的是「同步完成」
- R2 是这条 spec 规则的最后一句要求的：「**改完全文件搜一遍遍历**」——上次踩这条规则（#27）时就是漏搜
- 判据不是「有几处没加保护」，而是「**哪几处的数据来源可能不带结尾换行**」
