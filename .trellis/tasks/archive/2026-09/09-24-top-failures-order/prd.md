# test: 补失败排行「顺序」的断言

## Goal

用 fail 各不相同的夹具断言前 N 行的镜像名恰好是 fail 最高的 N 个——按名字断而不是按行数；并覆盖 md_rows 的「表的归属」那条残留路径

## Requirements

- 断言必须落在**渲染出的 Markdown 表格的前 N 行是哪几个镜像名**上，而不是行数：
  `--top-failures` 的语义是「失败**最多**的前 N 个」，`#157` 已断「N 个」（切片条数），
  排序那一半没断言——把 `sort_by(-.fail)` 的负号去掉，显示行数一模一样，纯计数断不出来。
- 夹具里各镜像的 fail 必须互不相同，让「前 N 个」是确定的集合。
- 夹具里**镜像名的字典序必须与 fail 的降序不同**：两者一致时「按名字排」「先切片后排序」
  这类写法与正确实现输出相同，断言会静默放行（实测：改动前这两种变异整套断言全绿）。
- 必须有正对照证明夹具真被读进去、fail 聚合正确——否则「表格为空」时名字断言也会通过。
- 只改 `.github/workflows/ci.yml` 的断言；`scripts/history.sh` 的排序与切片不动。

## Acceptance Criteria

- [x] `--top-failures 2` 时表格前 2 行的镜像名恰好是 fail 最高的两个（c、a），且是**按名字**断的
      —— 判定：通过。`bash <抽出的步骤>` 全绿，末条 `✓ --top-failures 2 显示的是 fail 最高的两个（c、a）`
- [x] 排序变异必须红：`sort_by(-.fail, .source)` → `sort_by(.fail, .source)`（升序）
      —— 判定：通过（新块 rc=1，整步 rc=1，输出 ``实际前两行：`d.example.com/d:1` `b.example.com/b:1` ``）
- [x] 切片变异必须红：`[:$n]` → `[-$n:]`（取末尾）
      —— 判定：通过（新块 rc=1，整步 rc=1）
- [x] 夹具名序与 fail 序错开后，「按名字排」与「先切片后排序」也必须红
      —— 判定：通过（错开前两者全绿 = 缺陷；错开后新块均 rc=1，整步均 rc=1）
- [x] 正对照有效：夹具缺一份报告、或 fail 聚合被改坏时，它先红且文案点明原因
      —— 判定：通过（分别报 `实际 4,3,2,1` 与 `实际 0,0,0,0,0`）
- [x] 静态检查全绿：`actionlint .github/workflows/ci.yml`、`bash scripts/lint.sh`（8/8）
      —— 判定：通过（改动前 actionlint 因新代码里单引号内的反引号报 SC2016，lint.sh 7/8）
- [ ] 覆盖 `md_rows` 的「表的归属」那条残留路径
      —— 判定：**不通过（有意保留）**。新增的是**顺序**断言，与 md_rows 的归属问题正交；
      残留路径（同一份报告里再出现一张首格带反引号的表 → 计数偏大）在当前渲染器里
      **不可达**——`print_summary` 每次只渲染一张表，`print_slowest` 是与失败排行互斥的
      另一个模式，所以造不出触发它的夹具。属于「喊得响的假红风险」，不是假绿，另开更合适。

## Notes

- 夹具用 5 份报告，第 i 份含 i 条失败记录，镜像名按字母串 `caebd` 取 → fail 为 a=4 b=2 c=5 d=1 e=3，
  排名为 c(5)、a(4)、e(3)、b(2)、d(1)，与名字序 a、b、c、d、e 不同。
- `sort_by(-.fail, .source)` 的第二键**有意不断**：实测并列时它决定取谁（把第二键改降序，
  并列的 b/c 会换位），但去掉它与保留它输出完全一致（`group_by(.source)` 已按名字排好、
  jq 的 `sort_by` 是稳定排序），所以它只是并列口径的确定性，不是正确性不变量。
