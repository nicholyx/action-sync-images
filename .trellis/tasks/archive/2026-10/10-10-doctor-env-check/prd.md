# --doctor 环境自检：把被动排障文档变成主动体检

## Goal

新增 `--doctor` 只读诊断模式：在同步 / 检查跑不起来或跑挂之前，主动回答「环境与配置能不能跑、
哪里坏了、怎么改」。逐项探测工具链、源/目标 registry 可达性、凭证、磁盘空间，失败项给出
可操作的修复指引并指向 `docs/TROUBLESHOOTING.md` 的对应锚点。**不推送任何镜像、不写任何文件。**

解决的真实痛点：skopeo 的底层报错（EOF / 401 / TLS / DNS）使用者难以定位是凭证、网络、
权限还是工具缺失；TROUBLESHOOTING.md 只能被动查阅，用户往往不知道该读哪一条。

## 决策（拍板）

1. **doctor 是「诊断」，不进四种模式语义矩阵**。矩阵回答镜像数据问题（跟上没 / 有无新版 /
   锁没锁住），doctor 回答环境问题——维度不同，强行进矩阵会让「检查对象」一行失去意义。
   在 modes.md 加一段「矩阵之外」的说明而不是加列。
2. **退出码：诊断全过 0；有任何失败 1**。1 是「环境没就绪 / 跑不了」的语义，与参数错误
   同族；2 保留给「环境是好的、检查发现了差距」的检查家族——不混用。
3. **不落盘、不通知**（第一版）：诊断结果是即时的，历史无聚合价值；用户主动跑的模式
   没有「失败了要打扰谁」的场景。`--report-dir` / 通知参数传入时进「本次不生效」告警列表。
4. **每一项探测可独立失败**：一项失败不中断其余探测（体检要看全貌，不是查到第一个病就
   停诊）；汇总行决定退出码。
5. **目标侧探测不推送测试镜像**：用「探测一个不存在的引用、期待 registry 给出
   manifest-unknown 类应答」证明 registry 活着且应答规范——不污染用户仓库。探测分类
   复用 probe_ref 的既有判据（连不上 / 未授权 / 应答正常）。
6. **与三种检查模式互斥（die）**：与 `--audit` × `--check-updates` 的既有互斥惯例一致，
   一次做一件事。同步参数（--dest 等）不强制：传了才探目标侧，没传就跳过该项并说明。
7. **jq 缺失的定档看 `--platforms`**（复查阶段拍板）：jq 不是无条件硬依赖——
   `ensure_jq` 的既有语义就是「缺了 warn，让用户装 jq **或显式传 `--platforms`**」。
   doctor 如实跟随：jq 缺失且未显式传 `--platforms` → `[失败]`（平台自动探测跑不了，
   指引两条路：装 jq 或显式传 `--platforms`）；jq 缺失但已显式传 `--platforms` →
   `[警告]`（本项无碍，但 `--src-credentials` 装载与报告生成仍依赖 jq，文案如实点名）。
   对环境明明能跑的配置报 `[失败]` + 退出码 1 是误伤——doctor 的哲学是「如实」，
   不制造假警报。

## Requirements

- 参数：`--doctor`（无值）。进入条件、互斥 die、不生效参数告警列表与既有模式同构。
- 探测项（MVP，每项一行输出 `[OK] / [警告] / [失败] + 详情`）：
  - **工具链**：skopeo 存在；jq 存在（定档看 `--platforms`，拍板 7）；regctl 仅在
    `--strip-attestation` 传入时才检查并说明原因
  - **源侧**：从 `--src` / `--file` 解析出的源 registry（按 host 去重）逐个探测可达性，
    分类输出（应答正常 / 未授权——提示凭证 / 连不上——提示网络与 TROUBLESHOOTING 锚点）
  - **目标侧**（传了目标地址时）：`--dest` 的 registry 应答性，同上分类
  - **凭证**：`--src-credentials` 传入时检查文件存在且可读；路径与 `--src-username` 的
    映射是否覆盖到全部源 host（漏配的 host 列出来）
  - **资源**：临时目录磁盘可用空间绝对值；并发 `--concurrency` 传入且 >1 时给需求估算提示
- 失败项后跟缩进的「怎么改」指引，含 TROUBLESHOOTING.md 的锚点链接（锚点必须真实存在，
  CI 断言钉住）。
- 汇总行：`诊断完成：N 项通过，M 项警告，K 项失败`；退出码按拍板 2。
- usage() 帮助、README 参数速查、USAGE.md 新场景、TROUBLESHOOTING.md 顶部加「先跑 --doctor」
  指引、CHANGELOG、modes.md「矩阵之外」说明全部同步。

## Constraints

- bash 3.2 兼容；退出码只取 0/1/2 体系。
- 每项探测带短超时，不给 registry 打重试风暴（诊断不是压测）。
- 不改动四种模式的任何既有行为；doctor 代码独立成函数群，不与同步主路径交织。
- CI 断言用 stub skopeo 造各失败形态（连不上 / 未授权 / 正常），本地 bash 3.2 实测通过。

## Acceptance Criteria

- [x] 全部探测通过（stub 正常应答）：退出码 0，汇总「0 项失败」。
- [x] 混合失败场景：工具缺失 / 源连不上 / 目标未授权同时存在——三项都各自报出（不中断），
      退出码 1，每个失败项都有「怎么改」指引与 TROUBLESHOOTING 锚点。
- [x] `--src-credentials` 指向不存在文件：报失败并给修复指引。
- [x] `--doctor` × `--audit` / `--check-updates` / `--audit-lock` 互斥 die，措辞与既有互斥一致。
- [x] `--report-dir` / 通知参数在 doctor 下进「不生效」告警。
- [x] regctl 只在 `--strip-attestation` 传入时被检查；未传时不检查也不告警。
- [x] 未传 `--dest` 时目标侧探测跳过且明说（不算失败）。
- [x] TROUBLESHOOTING 锚点全部真实存在（CI 断言逐个 grep）。
- [x] 四种模式既有 CI 断言全绿（回归不破）；本地 lint.sh 全绿。
