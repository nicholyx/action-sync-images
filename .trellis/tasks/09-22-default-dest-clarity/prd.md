# 默认目标仓库是作者的命名空间，而文档把它说成「可选」

## Goal

让使用者在**第一次同步之前**就知道：默认目标仓库是**项目作者示例用的命名空间**，需要改成自己的；如果他们确实在用默认值，也该在运行时被明确告知，而不是事后去猜。

## Background

### 现状

`sync-images-aliyuncs.yml` 与 `sync-images-batch.yml` 都有一行：

```yaml
DEST_REGISTRY: ${{ vars.ALIYUNCS_REGISTRY || 'registry.cn-shenzhen.aliyuncs.com/nicholyx' }}
```

`nicholyx` 是**项目作者的**阿里云命名空间。未设置 `ALIYUNCS_REGISTRY` 变量时，同步会推到那里。

### 三处文档都没说清

| 位置 | 现状 |
| --- | --- |
| `README.md` 的「快速开始」 | 三步（配置凭证 → 触发同步 → 拉取验证）里**完全没提**这个变量（0 次提及） |
| `docs/USAGE.md:108` | 「### **可选**：更换目标仓库」——默认值是作者的，但换仓库被描述成可选项 |
| `docs/TROUBLESHOOTING.md:175` | `denied` 的排查步骤只说「需要先在控制台创建命名空间（如 `nicholyx`）」，**没提这个根因**，而举例用的正是作者那个名字 |

第三条尤其容易把人带偏：使用者遇到 `denied` 去看排查步骤，会看到「创建命名空间（如 `nicholyx`）」——他不会意识到问题出在**默认值本身就是别人的**。

### 影响（如实分析，不夸大）

**这不是「必定失败」**。阿里云的命名空间是**账号内唯一、不是全局唯一**——使用者在自己账号下创建一个同名的 `nicholyx` 命名空间，推送会成功（只是推到了他自己的账号下）。所以这个默认值**有时能碰巧工作**。

真正的问题是**知情**：

- 使用者不知道自己在用作者的示例命名空间，也不知道这个值从哪来
- 它「碰巧能用」反而更隐蔽——直到他想换命名空间时才发现要设变量
- 对比 Harbor 工作流：`HARBOR_REGISTRY` 是**必填**，缺失时报 `::error::未配置 HARBOR_REGISTRY` 并退出。两个工作流的处理口径不一致：一个强制配置，一个静默用作者的默认值

### 为什么现在做

这是**首次使用者路径上的第一道坎**，而项目其余部分（快速开始、凭证说明、故障排查）都写得相当完整——只有这一处假设了「使用者会自己发现要改默认值」。

## Requirements

- **R1** `README.md` 的快速开始把「设置目标仓库」列为**一个步骤**（与配置凭证并列），而不是留给「可选」章节
- **R2** `docs/USAGE.md` 的「可选：更换目标仓库」改为**必填口径**：说清默认值是谁的、不设置会发生什么
- **R3** `docs/TROUBLESHOOTING.md` 的 `denied` 排查步骤补上这个根因，并修正「创建命名空间（如 `nicholyx`）」这种会误导的举例
- **R4** **三个工作流都加前置提示**（`sync-images-aliyuncs` / `sync-images-batch` / **`check-registry`**）：当目标仍是示例默认值、且**仓库 owner 不是作者**时，打印一条明确的告警（含「要换就设 `ALIYUNCS_REGISTRY`」的做法）

  > 实现阶段补记：本项初稿写的是「两个工作流」，**前提不完整**——`check-registry.yml` 的 `audit` 模式同样登录目标仓库并用它做体检，共用同一个默认值。而且那里的危害更大（见下），因此一并纳入。

- **R5** 提示**不阻断**同步，也不改变退出码——默认值可能是使用者的合法选择（见上文「不是必定失败」）
- **R6** 作者自己的运行**不受影响**（用 `github.repository_owner` 判断，不靠字符串猜）
- **R7** 不改默认值本身

## 为什么 `check-registry` 那一处危害更大

同一个默认值，在两条路径上的后果不同：

| 路径 | 不设置变量时 | 使用者能否发现 |
| --- | --- | --- |
| 同步 | 推送被拒（`denied`） | **能**——运行变红、有错误信息 |
| **体检** | **体检对象是作者的仓库** | **不能**——作者那边镜像齐全时，报告显示「全部最新」，而他自己的仓库其实是空的 |

体检给的是**结论**，而「全部最新」这个结论是**假绿**。这比推送失败更符合 `guides/index.md` 第 1 条「错误的信息比没有信息更糟，因为它会被当成结论」。

## Acceptance Criteria

- [ ] README 的快速开始能在第一次同步**之前**告诉使用者要设置目标仓库
- [ ] USAGE 不再把它说成「可选」
- [ ] TROUBLESHOOTING 的 `denied` 排查里能查到「默认值是作者的命名空间」这条
- [ ] 工作流的提示在「非作者仓库 + 未设置变量」时出现；作者仓库下不出现
- [ ] 提示不改变退出码与同步行为
- [ ] Aliyuncs / Batch / **Check-Registry 三个工作流**都覆盖（它们共用同一个默认值）
- [ ] `actionlint` / `yamllint` 干净；`./scripts/lint.sh` 全绿
- [ ] 全仓无 U+FFFD 与控制字符

## Out of Scope

- **不改默认值**：改成空值会让作者自己的运行失败；改成别的同样是把问题推给下一个人
- **不强制报错退出**：默认值可能是合法选择（使用者建了同名命名空间），报错会误伤
- **不动 Harbor 工作流**：它已经是必填 + 明确报错，是本任务要对齐的**范本**
- **不引入「首次使用向导」之类的机制**：超出项目定位（无服务端、无额外状态）
