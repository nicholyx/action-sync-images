# PRD：`--write-pending` + 输出路径守卫

对应 issue：[#173](https://github.com/nicholyx/action-sync-images/issues/173)（里程碑 v1.21.0）
守卫部分：[#172](https://github.com/nicholyx/action-sync-images/issues/172) 的第 1 条

## 一、`--write-pending`：把「需要动手的那部分」导出来

`--audit` 回答「清单与目标仓库的差距」，但**从体检到动手那一跳仍是手工的**。

现在的建议是「去掉 `--audit` 重跑同一条命令」（`--skip-existing` 会跳过已最新的），
但它有**两个洞**：

1. **`--strip-attestation`（regctl 路径）下 `--skip-existing` 不可用**——索引会被重建、
   目标 digest 必然不同，文档明确写着该组合不做跳过。这条路径上**没有**替代办法
2. 即便默认路径，`--skip-existing` 也要**对每个镜像各做一次 inspect**，大清单上是白跑一遍

### 验收标准

- [ ] **AC1**：`--write-pending <路径>` 与 `--audit` 同用，写出**落后 + 缺失**的**源引用**
      （一行一个），格式与清单完全兼容，可直接 `--file` 喂回
- [ ] **AC2**：与 `--write-updates` **同形**：按仓库分组（每组 `# <仓库>`）、组内版本序升序；
      头部同样写明「本文件不会修改你的清单」
- [ ] **AC3**：**「无法判定」不列入正文**，但头部必须报出个数并说明原因——它是「无从得知」
      而不是「需要同步」，两者不能混成一种（`--audit` 的退出码把三者都算 2，但**处置方式不同**）
- [ ] **AC4**：**不修改任何既有文件**（原清单字节不变，并与守卫联动）
- [ ] **AC5**：没有待同步项时**仍然写出文件**并注明
- [ ] **AC6**：只在 `--audit` 下生效；其他三种模式显式传入时进「本次不生效」合并告警
- [ ] **AC7**：日志报出「已写入 <路径>（N 行）」；条数与报告里的 `落后 + 缺失` 一致（**同源**）
- [ ] **AC8**：文档写清它与「去掉 `--audit` 重跑」的分工——**regctl 路径**与
      **「不想白跑一遍 inspect」**时用它

### 已核实的前提

- 状态取值：`current` / `stale` / `missing` / `unknown`（`sync.sh:2184-2212`），`excluded` 单独计数
- 记录形状：`src`⟨US⟩`dest`⟨US⟩`state`⟨US⟩`note`（`write_audit_result()`）——**源引用就在记录里**
- 报告 summary 的键：`current` / `stale` / `missing` / `unknown` / `excluded`

### 实现时必须自己核实的两点

- **`excluded` 有没有记录行**？若有，它绝不能进子集——使用者有意排除的东西不该被重新建议同步
- **一个源对应多个目标**时记录是「源 × 目标」一条——子集里同一个源**只能出现一次**

## 二、输出路径守卫（#172 第 1 条）

`--write-updates images.lock.txt` 会把清单**覆盖**成片段，而生成的文件头部还写着
「本文件不会修改你的清单」——声明与行为自相矛盾。

### 验收标准

- [ ] **AC9**：**输出路径不得与本次读入的任何文件相同**（`--file` 清单、`--src-credentials`、
      `--audit-lock` 的锁文件），用 `[[ A -ef B ]]` 判断（能覆盖 `./x`、符号链接、
      相对/绝对路径等指向同一文件的情形），命中即 `die` 并说明「输出路径与输入文件相同」
- [ ] **AC10**：守卫**一处实现、三个写出参数共用**（`--write-updates` / `--write-pending` /
      `--write-lock`）——同一个洞不该在三个地方各修一遍
- [ ] **AC11**：断言覆盖「命中即拒绝」与「正常路径不被误伤」两侧；并断言被保护的文件
      **字节不变**

## 边界

- **不自动改清单**：仍然是「生成建议、人来做决定」
- **不改变 `--audit` 的退出码语义**（本任务只新增一个输出通道）
- `--skip-existing` 与 regctl 路径的关系**一个字不改**——文档只是说清分工

## 不做什么

- 不处理 #172 的第 2 条（「上游返回空 tag 列表」算干净还是异常）——那是语义决定，仍待拍板
- 不把 `--write-pending` 暴露成 Action input（要配 artifact 上传才有意义，留待需要时）

## 风险

- 多目标下「同一个源出现一次」容易写错（记录是源 × 目标）——这正是要断言的
- 守卫若用字符串比较而非 `-ef`，`./images.lock.txt` 与 `images.lock.txt` 会漏
- `--write-lock` 的写出发生在同步循环**之后**，守卫要在**参数校验阶段**（动任何东西之前）就跑
