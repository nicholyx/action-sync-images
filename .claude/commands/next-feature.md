## 本轮目标

- **开箱即用体验与可靠性并重，都是第一优先级**：
  - 易用——inputs 文档清晰、dry-run 预览直观、报错信息能让用户直接知道怎么改；
  - 可靠——同步结果正确、幂等可重跑、失败可恢复（镜像同步场景的硬指标）。
- **敢于创新**：做出有特色、有想象力并且与众不同的功能。
- 可自行检索其他同类镜像同步 Action / 工具，对比跟我们的差异，把优秀的内容吸收过来——
  但**不能一味复制**，要经过融合改造，无缝融入本项目。

## 硬性要求

- 动 `scripts/sync.sh` 前必读 `.trellis/spec/engine/`（bash 3.2 硬规则 + 四种模式语义矩阵）；
  改 CI 工作流前必读 `.trellis/spec/workflows/`（供应链基线与红线）。
- **测试全部补齐**：新功能要加进 CI 的 smoke-test / integration-test 断言；
  本地先过 `./scripts/lint.sh`（actionlint / yamllint / shellcheck / bash -n / zizmor）。
- 确保新加的每一个功能都**不影响老功能**（CI 回归必须全绿）。
- 涉及同步行为的改动，尽量在本地用 Docker 跑一次真实推送或 dry-run 验证，
  别只依赖 CI 远端验证。
- `./scripts/lint.sh` **不验提交信息规范**：PR 标题与提交信息仍要按约定式提交自己把关。
